## 缓存与更新

`art-loader.js` 读取构建时生成的静态清单，提供同步奇物映射与带内容 SHA 的资源 URL，替换原来运行时才请求 JSON 再补图的方式。`art-sw.js` 仅为清单内静态 GET 请求提供 CacheStorage 缓存；相同资源的预取和实际展示共享进行中的请求。

缓存键按文件 SHA 区分版本。正常刷新和后续旅程复用已有字节，更新一张图只下载变化项。旧页面仍可使用已有旧 SHA 缓存；下载内容需通过 SHA 校验，不会把新版字节放入旧版本键。API、HTML、统计、存档、跨域与未知查询参数不被截获。

Service Worker 不可用时保留已核验图片的 Blob 供本页显示；持久存储拒绝时另有有界会话内存回退。已适配 Pixi 的显式图片解析、Effekseer PNG 路径与受控 Blob 的展示白名单。没有 Worker 时，部分代码/二进制依赖仍可能再次请求，不能承诺完整的跨页面零网络。

持久复用需要 HTTPS（本机 localhost 也受支持）及浏览器允许存储；用户清除站点数据或浏览器回收缓存后会重新加载。这是美术缓存，不是整个游戏的离线安装包。依据：[MDN Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API)、[MDN CacheStorage](https://developer.mozilla.org/en-US/docs/Web/API/CacheStorage)。

## 构建与维护

`npm run build` 会先运行 `scripts/generate-art-assets.mjs`，再复制产物，确保页面与 Worker 使用相同清单。仅修改资源后直接用静态服务器预览时，先执行：

```sh
node scripts/generate-art-assets.mjs
```

图片压缩不是每次构建的步骤；`scripts/optimize-art.py` 使用母版按审计哈希跳过已完成文件，避免重复有损编码。当前版本的缓存清单为 `2a06a2055895ef62b041`。

## 实际验收

- 新端口无缓存首访：服务器记录恰好 41 次美术请求、719,333 B，没有重复，尚未加载后续资源。
- 进入旅程：补齐到 99 次请求、11,553,850 B，没有重复。核心卡图与麻将牌面正常显示。
- 服务器对所有图片、字体、WASM、粒子文件返回失败后，刷新、继续游戏和播放九莲结算仍成功；新增美术网络请求为 **0**。固定 QA 场景结果为 19,660,800，与正式引擎预览一致。
- 本地服务器只改变一张一万 SVG 的内容版本，重新进入仅下载该图一次；其余缓存复用。该实验没有修改生产源图片。
- 在另一全新端口令 Worker 注册失败：首屏与九莲完整演出正常，Blob 牌面、奇物、主题及粒子加载成功。此降级场景有 9 次额外依赖/即时图片请求，未将其算作正常缓存模式的零重复结果。
- 独立代码审阅已修复存储不可用时重复下载、Blob 图片解析、加载中 URL 变化和背景引用更新问题；99 项清单的 SHA 与文件大小全量匹配。
- 独立模拟验证跨版本缓存、存储拒绝、联网恢复、请求范围隔离与后台并发；没有新增长期自动化测试脚本。已有结算适配器 10 项回归测试及 `npm run build` 通过。

机器可读记录：[art-loading-validation.json](art-loading-validation.json)。本地真实请求日志与截图位于项目父目录 `outputs/art-loading-20261022/`。本轮未提交、未部署；没有改动玩法、计分、奖励或存档格式。未测真实手机网络耗时及线上发布后的缓存头配置。

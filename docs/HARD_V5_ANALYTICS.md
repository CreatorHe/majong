## 身份与兼容

| 玩法 | 规则身份 | 计分身份 |
| --- | --- | --- |
| 轻松 V9 | `nine_batch_v9` | `fan_score_v9` |
| 本次恢复的高难 V5 | `hard_opening_build_v5` | `hard_four_core_v5` |
| 历史 V5 | `opening_build_v5` | `four_core_v5` |

高难引擎仍使用原 V5 的 `version / rulesVersion / scoreVersion`。共享适配器只在 `version === 5 && variant === 'hard_v5'` 时映射新的上报身份；不改引擎分数、牌或存档。高难入口使用独立存档，生成独立旅程、关卡和结算 UUID，不迁移旧 V5 存档。

复用现有 API、D1 表和匿名采集偏好，无数据库迁移。所有聚合始终限定规则与计分身份，旧 V2–V9 事件沿用原校验和分母。本次高难与历史 V5 绝不混算。

轻松模式保留原有 `jade-run:analytics:v1:production` 待发送队列与锁；高难新增 `jade-run:analytics:v1:production:hard_v5` 独立队列、匿名写入身份和锁。两种玩法可以同时在不同标签页采集，互不阻塞、互不覆盖。每种玩法内部仍保留单写入页保护。匿名采集偏好和撤回通知共用，关闭统计会同步停止两个正在运行的采集器并清空各自队列；同时写入共享撤回标记，已关闭页面的旧队列在下次恢复时失效，重新开启统计也不能复活。未发生撤回、没有新标记的旧 V9 快照继续正常恢复。旧离线事件版本、编号及轻松队列路径保持不变，新会话使用对应玩法身份。

## 看板

- `/analytics/?variant=easy_v9`：轻松模式；不带筛选参数的 API 也继续默认 V9。
- `/analytics/?variant=hard_v5`：高难模式；按国标与日麻分别展示摘要、番型、得分纪录与四路线表现。
- `variant=history`：查看早期版本，保留原 V5 与其他历史统计。
- 高难可加 `core_id=core_high / core_pung / core_held / core_growth`，摘要和番型分母同步限定同一路线。服务端拒绝与轻松、历史规则混搭的筛选。
- 游戏里的统计入口会进入对应玩法报表，返回牌桌也回到对应入口。

四路线摘要从完整观测终局的 `owned_relic_ids` 归属核心，展示结算关数、合法和牌数、单关过关率、平均本关净分和最高和牌分。这里只是**已结算关卡**的表现，未结算退出不进入分母，不能解释为全开局胜率或整趟通关率。诈胡仍达标保持原过关口径，合法和牌分母不包含诈胡。

统计页原有测试写入工具仅生成 V9 测试样本；高难页禁用该按钮，避免把轻松 fixture 当作高难数据。

# 叠雀 Web 原型 · V4

单人麻将肉鸽。选择国标番型或日麻役种，自由出牌构成完整麻将手牌，用奇物、改牌和换牌提高得分，累计分达到六关逐步提高的门槛。

V4 的保留候选规则与构筑联动提示已在本地实现，本轮定向浏览器验收已完成，详见[验收记录](docs/V4_BROWSER_VALIDATION.md)。新版结算爆发动效尚未集成。

## 本地运行

完整数据服务需要 Node.js 22.13+，游戏使用原生 JavaScript，服务端为 Worker + D1。

```sh
npm install
npm run dev
```

游戏地址：`http://127.0.0.1:4175/`，统计页：`http://127.0.0.1:4175/analytics/`。启动命令会构建并应用尚未执行的本地数据库迁移；本地数据保存在 `.wrangler/state/`，与线上数据库隔离。

只预览玩法可使用 Python 3：

```sh
npm start
```

打开 `http://127.0.0.1:4173/`。纯静态入口不含采集数据接口。游戏进度保存在当前浏览器；停止预览按 Ctrl+C。

## 部署

项目使用 Vite、Cloudflare Workers 和 D1。Node.js 需为 22.13 或更新版本。部署前安装依赖并登录 Cloudflare：

```sh
npm install
npx wrangler login
npx wrangler d1 create jade-run
```

从 `d1 create` 的结果复制数据库 ID，然后设置 `CLOUDFLARE_D1_DATABASE_ID` 并运行部署命令：

```sh
CLOUDFLARE_D1_DATABASE_ID=<你的数据库 ID> npm run deploy
```

部署脚本会构建 Worker 和静态资源、应用 `drizzle/` 中的远程迁移，再发布 Worker。游戏和 `/analytics/` 共用同一域名；匿名统计由 D1 保存。数据库 ID 只需在本地 shell 或部署环境变量中设置，不要提交到仓库。只需托管纯静态文件时，`dist/` 可交给任意静态文件服务器，但采集接口和统计页需要 Worker 才能工作。

## 玩法

- 游戏内提供双模式番型图鉴，区分“直接支持”“需要奇物”“本作不适用”，显示条件、番／翻和解锁要求。国标完整列出 81 个标准番型，其中 59 个可判定、22 个不适用，另列 3 项奇物扩展；日麻共列 54 项，其中 27 项可判定、3 项需奇物、24 项不适用。
- 每次可放单张或多张进成型区，不要求固定的 3+2。提交批次不锁面子，最终比较本模式支持的所有解释并选收益最高者。两模式支持普通结构、七对、国士无双／十三幺；国标额外支持组合龙、全不靠／七星不靠，以及四张同牌拆成七对中的两对。日麻七对子仍须七种牌，六张同牌不能当三对。
- 四张相同牌可显式声明杠，支持备选和成型两区凑牌。杠占三个结构位置、保留四张实牌；完整手为 14 个结构位置、`14 + 杠数` 张实牌。杠声明后不能拆开或改写。
- 初始 12 张候选、7 次换牌、4 点墨。出几张实体牌就补几张，未选牌保留；声明杠只补实际从候选移入的牌，纯成型区声明不补牌。没有开局顺子／对子保底。第三关减少 2 次换牌，借东风增加 2 次。
- 主动换牌每次只换所选 1～5 张，与非杠成型牌的等量替换共用次数；替换后仅补实际移入数量，保留其余候选。填满成型区仍会等量补牌供确认前修牌；墙空少补或不补，弃牌不回收、不复制。无杠基础曝光上限为 `12 + 14 + 7×5 = 61` 张，单张提交不再免费刷新整批。
- 沿用 21 件奇物，本轮不增加奇物。独行印奖励每关前四次有效单张出牌、四方鼎奖励杠；升降笔、换色绫、百相玉分别解锁改点数、改花色、花色万能牌。
- 花色万能牌保留点数，可当万／筒／索，不能替代字牌；每关最多生成一张。一个最终解释只使用一种确定花色，显示与所有番型、奇物共用该解释。
- 牌形风险提前提示，允许明确确认后继续危险出牌。满 14 个结构位置后仍可修复，也可主动确认终局；计算异常不会当作玩家炸胡。
- 构筑面板展示已持有奇物的材料进度、成长和资源，只统计成型区；尚未提交的候选不算进度，未成型不保证可补齐。满 14 后按真实最高分解释点亮有效计分奇物，显示实际底分与倍率；改牌破坏条件或切换解释时立即撤销。炸胡关闭计分联动，但保留改牌和资源提示。
- 每关只结算一次。合法和牌加分；不成立则炸胡扣分。两者均按更新后的**挑战累计分**判断过关，炸胡后仍达门槛也可正常领取通关奖励。
- 前五关达标后免费选择奇物，再进入可购买、刷新、出售的商店；第六关达标登顶。分数、铜钱、奇物和永久成长跨关保留；牌墙、成型区、单关改牌效果和资源按新关重置。
- 结算演出按引擎冻结的牌面、番型、奇物和计分步骤播放；高分、高倍率、高番型独立分档。跳过、重播或恢复结算页不会重复加减分或发奖。

## 计分与规则边界

这是使用麻将番型的肉鸽改编，不是完整竞技麻将模拟器。所有支持结构共用每关门槛；不要求国标八番起和或日麻有役，不使用符数、竞技支付点数和满贯封顶。标准番型直接判定，不需要奇物解锁。图鉴完整列出对照项目，但不把缺少对局依据的役种算作已实现：本作没有自摸／荣和、立直巡目、场风／自风、明暗刻历史或指定和牌张，相关项目明确显示“不适用”及原因。

车轮秘卷解锁日麻大车轮，国标是在原有连七对之外额外加赏；连山印解锁日麻三连刻，国标是在原有一色三节高之外加赏；将令解锁地区扩展将将胡。这三类奇物奖励不改变标准番型是否成立。

```text
本关净分 = 过程分 + 和牌分 − 炸胡罚分
终局累计分 = 终局前累计分（已含过程分）+ 和牌分 − 炸胡罚分
过关条件 = 终局累计分 >= 本关累计门槛
```

合法和牌的底分覆盖全部最终实牌：数牌各 10、字牌各 15、完整和牌奖励 100，再加奇物底分。V3 改为指数倍率：日麻 `2^(翻 / 2)`，国标 `2^(番 / 8)`，即每增加 2 翻／8 番，番型倍率翻倍。番值先完成模式内互斥与复合判定，再求指数；此后沿用聚宝钱等加倍率项、奇物乘倍率项与 Boss 因子的既有顺序。倍率以引擎保留的 6 位小数为权威值，和牌分为 `floor(底分 × 最终倍率)`；演出读取同一结果。过程分不会重复加入和牌分或再整体乘番。

V4 沿用六关累计门槛：国标 `300 / 1800 / 8000 / 40000 / 180000 / 1000000`；日麻 `240 / 1200 / 5000 / 18000 / 75000 / 300000`。这些是与指数计分配套的试玩初值，尚无 V4 真人通关率或平衡结论。

炸胡罚分试玩值为 `ceil(本关累计门槛 × 10%)`，允许负分；炸胡不触发要求合法和牌的番型收益、奇物加分和终局成长，但扣分后仍达标会得到正常通关奖励。已经超过门槛也需要完成终局，不能自动跳关。

改牌保留每张牌的实体 ID，不再从牌墙找目标牌交换。实体总数保持 136 张、每种原始牌四张；改写后的有效牌面允许超过四张。重复同种箭刻不能冒充不同种箭牌触发大三元。

V4 使用 `free-play-v4` 规则，沿用 `exponential-v3` 计分版本，使用独立的 `jade-run-v4` 浏览器存档，并保留稳定的挑战／关卡／结算 ID。V1～V3 原始存档保留，不静默迁移或覆盖，旧局不能在 V4 引擎中续玩。当前门槛、奇物数值和后半程难度仍为试玩参数。

## 验证与试玩模拟

核心验收以本机浏览器实际试玩为主，自动化只补 P0 核心回归，长期准则见 [AGENTS.md](AGENTS.md)。V4 本地已实际验证候选保留、等量补牌、主动换牌、候选四张声明杠及第三关资源；车轮组合从 13 到 14 张时四件奇物联动，改坏后熄灭、修复后恢复，真实试算与结算均为 48,875 分，随后领奖、商店和下一关重置流程通畅。详见[浏览器验收记录](docs/V4_BROWSER_VALIDATION.md)及[玩法计划第 12、13 节](docs/FREE_PLAY_AND_SETTLEMENT_PLAN.md)。这是本机桌面定向场景验证，不代替实体手机、跨浏览器、听感或真人胡率验证。

```sh
npm test
```

`npm test` 覆盖引擎、已接入的演出适配与数据链路测试。沿用已有脚本，只补关键牌形、番型、指数计分、候选保留与联动结果一致性等 P0 回归；脚本通过不能替代实际试玩。

以下平衡脚本说明与结果为 **V2 历史记录**。其后候选补牌、番型范围、计分和门槛均已变化；旧策略与旧运行结果不适用于当前 V4 难度评估，也不是 V4 真人通关率。V4 参数的精确概率与研究性策略模拟见[抽牌调研](../research/2026-10-21-draw-competitors.md)，不加入游戏自动化回归入口。

原 V2 脚本调用方式保留供查阅，不作为 V4 验收命令：

```sh
node scripts/balance-check.mjs
node scripts/balance-check.mjs 20
```

平衡脚本默认每个组合运行 100 个固定种子，共六个组合：两种模式 × 温玉／独行印／升降笔开局。参数可指定 1～1000 个种子。输出首关合法数与达标数、首关分数区间、通关关数分布和可复现的最佳种子。

模拟只通过真实 V2 操作接口构筑普通手、声明杠、换牌、使用已持有的改牌能力和领取奖励；不读取未来牌墙、不注入牌或分数，每局结束还验证可恢复存档。策略是基于可见牌的简单贪心，不擅长七对和高阶奇物组合；结果用于发现流程卡死和明显数值偏差，**不代表人类玩家胜率或已完成平衡验证**。

2026-10-21 的 100 种子验算结果如下；每格为完成次数／100。六组共 600 局均到达终局且存档可恢复。

| 模式 | 开局奇物 | 首关合法 | 首关达标 | 六关通关 |
| --- | --- | --- | --- | --- |
| 国标 | 温玉 | 100 | 99 | 47 |
| 国标 | 独行印 | 100 | 100 | 50 |
| 国标 | 升降笔 | 100 | 99 | 43 |
| 日麻 | 温玉 | 100 | 100 | 34 |
| 日麻 | 独行印 | 100 | 100 | 29 |
| 日麻 | 升降笔 | 100 | 100 | 17 |

上述 V2 历史结果对应累计门槛为国标 `300 / 700 / 1250 / 2100 / 3400 / 5200`，日麻 `240 / 700 / 1300 / 2200 / 3500 / 5400`。当时日麻首关从 300 调至 240，使本作允许的基础无役合法手可以通过首关；后续门槛保持不变。该组数据不可用于推断当前 V4 的通关难度。

构建验证：

```sh

```

`tests/browser-harness.html` 是复用的浏览器验收入口：完成本地构建后临时复制到 `dist/client/__qa.html`，重启本地 Worker 后访问 `/__qa`；重新构建会清除它，发布前须重新构建。`tests/tile-gallery.html` 为独立牌面验收页；均不随游戏发布。可从项目根运行 `python3 -m http.server 4174 --bind 127.0.0.1` 后打开 `http://127.0.0.1:4174/tests/tile-gallery.html`。

## 文件与素材

玩法规范见 [自由出牌与结算计划](docs/FREE_PLAY_AND_SETTLEMENT_PLAN.md)。数据采集与统计由独立适配层维护，接口、部署边界和实际交付范围见 [采集接入说明](docs/ANALYTICS_IMPLEMENTATION.md)；纯静态预览不代表服务端已接入。

- `dist/engine.js`：状态迁移、番型计分、奇物、关卡与不可变结算快照。
- `dist/hand-rules.js`：完整拆解、花色万能解释和保留现牌的补牌可达性检查。
- `dist/riichi-patterns.js`、`dist/mcr-patterns.js`：双模式番型目录、判定与复合规则。
- `dist/pattern-catalog.js`、`dist/pattern-guide.js`：包含奇物解锁及不适用原因的游戏内图鉴。
- `dist/app.js`：游戏页面、交互与浏览器存档。
- `dist/build-hints.js`：只读的成型区材料进度与真实结算联动提示，不另行计分。
- `dist/settlement-adapter.js`、`dist/settlement/`：冻结结果到演出数据的适配、播放器和音效。
- `dist/tiles.js`、`dist/art/tiles/`：34 种本地 SVG 麻将牌面。
- `dist/style.css`：桌面与手机布局。
- `dist/art/manifest.json`：奇物和背景图片索引，缺失素材保留可玩占位。
- `scripts/balance-check.mjs`：可复现的 V2 试玩模拟。

V2 扩展的奇物固定 ID 为 `single_seal / kong_cauldron / rank_brush / suit_ribbon / wild_jade`；与原 16 件一起沿用，本轮未增加奇物。`single_chain` 连星珠仅作美术储备，本版本未投放。

运行素材使用 WebP，原始制作文件在上级 `art/` 中保留。麻将图案改编自 [FluffyStuff 的 CC0 麻将矢量素材](https://github.com/FluffyStuff/riichi-mahjong-tiles)，调整配色并绘制蓝框白板，授权记录见 `dist/art/tiles/LICENSE.md`。无需下载麻将字体。
